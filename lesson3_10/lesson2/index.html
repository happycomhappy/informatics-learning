지난 시간에 우리는 「기준」을 코드로 적었다

조건문과 반복문을 함께 써서 청소 당번을 뽑고, 몬스터를 건너뛰고, 멈추게 했습니다. 오늘은 그 코드를 교실 밖으로 가지고 나가 봅니다.

되짚기 — 우리가 만든 코드 세 조각

① 중복 없이 3명 뽑기4차시 화면 3
selected = []

while len(selected) < 3:
    pick = random.randint(1, 8)

    if pick not in selected:
        selected.append(pick)

print(selected)
② 건너뛰기와 멈추기4차시 화면 4
for monster in range(1, 50):
    if monster == 7:
        continue

    if monster == 33:
        break

    print(f"{monster}번 처치!")
  • 조건문은 「무엇을 기준으로 가를지」를 정합니다. pick not in selected, monster == 7 처럼요.
  • 반복문은 그 기준을 사람이 보지 않는 사이에 수없이 되풀이합니다.
  • 그래서 조건 한 줄은 한 번의 판단이 아니라 규칙이 됩니다.

화면 2 · 생활 속 사례 ① · 4분

청소 당번 뽑기에 한 줄이 늘었다

지난 시간 코드에 조건 하나가 덧붙었습니다. 무엇이 달라지는지 보세요.

지난 시간 코드 — 공정한 추첨그대로
selected = []

while len(selected) < 3:
    pick = random.randint(1, 8)

    if pick not in selected:
        selected.append(pick)

pick not in selected 는 이미 뽑힌 사람을 다시 뽑지 않기 위한 조건입니다. 누구에게나 똑같이 적용되므로 아무도 불만을 말하지 않습니다.

교실에서 실제로 일어난 일한 줄 늘었다
selected = []
excluded = [7]          # 7번은 빼 달라는 부탁을 받았다

while len(selected) < 3:
    pick = random.randint(1, 8)

    if pick not in selected and pick not in excluded:
        selected.append(pick)

늘어난 것은 and pick not in excluded 열다섯 글자입니다. 그런데 7번은 이 프로그램에서 한 번도 뽑히지 않습니다. 이번 주만이 아니라, 이 코드를 쓰는 동안 계속입니다.

  • 반복문이 규칙으로 굳힌다. while 은 조건을 만족할 때까지 되풀이하므로, 7번을 건너뛰는 판단도 끝까지 되풀이됩니다. 「한 번 봐주기」가 「영구 제외」가 됩니다.
  • 결과만 보면 알 수 없다. 화면에는 [2, 5, 8] 같은 숫자만 나옵니다. 반 친구들은 이것을 「무작위 추첨」이라고 믿습니다.
  • 내 번호가 거기 있는지 나는 모른다. excluded 목록을 볼 수 있는 사람은 코드를 가진 사람뿐입니다.
생각해 볼 것 — 짝과 한 마디씩만 (쓰지 않아도 됩니다)
  1. 다리를 다친 친구를 빼 주는 것은 배려일까요, 특혜일까요? 무엇이 달라야 배려가 될까요?
  2. 이 코드를 반 전체에게 보여 주었다면 결과가 달라졌을까요?
  3. excluded = [7] 이 excluded = [7, 2, 5] 로 늘어나는 것을 누가 막을 수 있을까요?

나의 입장 고르기

정답이 없는 질문입니다. 지금 생각에 가장 가까운 것을 하나 고르고, 까닭을 한 줄로 적어 보세요.

더 알아보기 — 「알고리즘은 공정하다」는 말

무작위 추첨은 그 자체로는 공정합니다. 공정함이 깨지는 곳은 난수 생성기가 아니라 조건문입니다. 누구를 후보에 넣고 누구를 뺄지는 사람이 정하고, 프로그램은 그 결정을 조용히 되풀이할 뿐입니다.

그래서 어떤 자동 판단을 두고 「공정한가?」를 물을 때는, 결과보다 먼저 어떤 조건이 적혀 있고 그것을 누가 볼 수 있는가를 묻습니다. 이것을 투명성이라고 합니다.

화면 3 · 생활 속 사례 ② · 3분

continue — 조용히 건너뛰면 기록이 남지 않는다

지난 시간 7번 몬스터를 건너뛰었을 때, 화면에는 아무 흔적도 남지 않았습니다.

지난 시간 — 7번은 건너뛰었다4차시 화면 4
for monster in range(1, 50):
    if monster == 7:
        print("7번은 함정! 피해서 지나갑니다.")
        continue       # 이번 회차만 건너뛰고 8번으로

여기서는 건너뛰기 전에 print() 가 있었기 때문에 건너뛴 사실이 보였습니다. 그 한 줄이 없었다면 7번은 그냥 사라졌을 것입니다.

교내 봉사 동아리 지원자 자동 정리지원자 200명
passed = []

for person in applicants:          # 200명
    if person["grade"] == 3:
        continue                  # 3학년은 건너뛴다

    if person["score"] < 80:
        continue                  # 80점 미만은 건너뛴다

    passed.append(person)

print(len(passed), "명이 통과했습니다")

화면에는 42명이 통과했습니다 만 나옵니다. 나머지 158명에게는 떨어졌다는 기록도, 까닭도 남지 않습니다.

  • continue 는 「없었던 일」로 만든다. 반복을 끝내지 않고 그 사람만 지나칩니다. passed 에도 없고, 떨어진 명단에도 없습니다.
  • 한 줄이 200명에게 똑같이 닿는다. 쓴 사람은 조건 하나를 적었을 뿐이지만, 반복문은 그것을 200번 집행합니다.
  • 말할 기회가 사라진다. 사람이 심사했다면 「3학년인데 꼭 하고 싶습니다」라는 말을 들을 수 있었습니다. continue 는 그 말을 들을 자리를 없앱니다.
생각해 볼 것 — 짝과 한 마디씩만
  1. 건너뛰더라도 기록은 남기려면 코드를 어떻게 고치면 될까요? (continue 앞에 한 줄을 넣는다면 무엇을 넣겠습니까?)
  2. 두 조건 중 어느 쪽이 더 문제라고 느껴집니까? grade == 3 과 score < 80, 왜 그렇습니까?
  3. 내가 158명 중 한 사람이라면, 무엇을 알려 달라고 요구하고 싶습니까?

나의 입장 고르기

정답이 없는 질문입니다.

더 알아보기 — 「설명을 들을 권리」

자동으로 사람을 가르는 시스템에는 보통 세 가지를 요구합니다. ① 어떤 기준으로 가르는지 미리 알리기, ② 결과와 함께 까닭을 알려 주기, ③ 다시 봐 달라고 말할 수 있는 길을 열어 두기. 코드로 보면 각각 기준 공개 기록 남기기 사람이 다시 보기 입니다. continue 하나가 이 셋을 모두 건너뛸 수 있습니다.

화면 4 · 생활 속 사례 ③ · 3분

멈추라고 적지 않으면 멈추지 않는다

지난 시간 33번 보스에서 break 를 만나 반복이 끝났습니다. 그 한 줄이 없으면 어떻게 되는지, 우리가 매일 쓰는 것으로 봅니다.

지난 시간 — 33번에서 반복 전체가 끝났다4차시 화면 4
for monster in range(1, 50):
    if monster == 33:
        break      # 34~49번은 아예 실행되지 않는다

break 는 멈추는 조건입니다. 멈출 조건을 적어 두지 않으면 반복은 끝까지, 또는 영원히 돕니다.

영상 한 편만 보려고 했는데

아래 두 코드는 같은 반복문입니다. 다른 곳은 마지막 두 줄뿐입니다.

㉮ 멈출 곳을 정해 둔 코드break 있음
count = 0

while True:
    play_next()      # 다음 영상
    count = count + 1

    if count == 3:   # 3편만 본다
        break        # 반복 끝

3편에서 끝납니다 ✔
멈추는 조건이 코드 안에 적혀 있기 때문입니다.

㉯ 자동 재생break 없음
count = 0

while True:
    play_next()      # 다음 영상
    count = count + 1

    # 멈추는 줄이 없다

끝나지 않습니다 ✕
사람이 꺼야 끝납니다. 코드는 끝낼 생각이 없습니다.

우리가 쓰는 자동 재생은 ㉯ 쪽입니다. break 두 줄을 적지 않기로 한 것도 사람이 내린 결정입니다.

  • 조건을 「넣는 것」만 결정이 아니다. 사례 ①은 조건을 넣어서, 여기서는 조건을 넣지 않아서 일이 생깁니다. 둘 다 사람이 정한 것입니다.
  • 끄는 일을 사람에게 넘긴다. 다음 편이 5초 뒤에 저절로 시작되면, 멈추려는 사람은 매번 한 번 더 손을 써야 합니다.
  • 그래서 「의지」의 문제로 보이게 된다. 멈추지 못한 사람을 탓하기 전에, break 를 쓸 수 있었던 사람이 누구였는지 봅니다.

내 마음속 break 는 몇 편이었나

어제나 그제를 떠올려 적어 보세요. 아무에게도 보내지 않습니다.

두 칸이 다르다면, break 는 내 마음속에는 있었지만 코드 안에는 없었다는 뜻입니다.

㉮처럼 조건으로 써 보세요 — if count == 3: break

생각해 볼 것 — 짝과 한 마디씩만
  1. 마음속으로 정한 양과 실제로 본 양이 달랐다면, 무엇 때문에 달랐을까요?
  2. ㉯에 break 를 넣는 줄은 누가 쓸 수 있습니까 — 나, 만든 회사, 보호자?
  3. 자동 재생을 끄는 설정이 있다면, 그것은 왜 처음부터 켜진 채로 있을까요?

나의 입장 고르기

정답이 없는 질문입니다.

더 알아보기 — 세 사례를 한 줄로 묶으면
  • 사례 ① if ... and pick not in excluded — 누구를 후보에서 뺄지 정하는 조건
  • 사례 ② continue — 건너뛴 사실을 남길지 정하는 자리
  • 사례 ③ break 가 없음 — 언제 멈출지 아무도 적지 않은 자리

①은 조건을 넣어서, ②는 기록을 남기지 않아서, ③은 멈춤을 적지 않아서 일이 생겼습니다. 넣는 것도 안 넣는 것도 사람이 정합니다.

셋 다 기술이 고장 난 이야기가 아닙니다. 코드는 적힌 대로 정확하게 돌았습니다. 문제는 무엇을 적고 무엇을 적지 않았는가에 있었습니다.

모둠 토론 기록

쟁점: (화면 6에서 쟁점 문장을 먼저 적어 주세요)

1단계 · 돌아가며 말하기 — 한 사람 1분
